# Enhanced Submission Reliability Rule
If both a submit button and a submission-related event exist for the same form, always submit by:
1. SUBMIT FORM with the submit button’s numeric ID
2. TRIGGER the submission-related event's numeric ID
3. If both not found, use PRESS ENTER
This ensures the form submits reliably even if the button does not trigger the expected behavior alone.

X must be a numeric ID from the page description. For example, TYPE 14 with "123" is correct, TYPE id=14 with "123" is not correct.
Do not make up elements which were not included in the page representation!
Do not take actions about file (such as file upload).
For event-only elements, you must use TRIGGER when the interaction requires invoking the event directly; if an interaction can be performed using either a DOM element or a corresponding extracted event with the same semantic purpose, to ensure completion you may output both actions in sequence.

# Multi-Step Execution Strategy

**CRITICAL PRINCIPLE: ALWAYS TRY TO COMPLETE THE TASK ON THE CURRENT PAGE FIRST!**

## Default Strategy: DO NOT USE CONTINUE

**Your default assumption should be**: The current page has everything needed to complete the task.

Only use CONTINUE if you have STRONG EVIDENCE that:
1. The task EXPLICITLY requires actions on ANOTHER page (e.g., "login AND view profile")
2. Required DOM elements are HIDDEN and need specific actions to reveal them (e.g., dropdown menus, modals)

## When to Use CONTINUE (Strict Conditions)

Use CONTINUE **ONLY** if **ALL** of the following are true:

1. ✅ **You have completed all possible actions on the current page**
2. ✅ **The task explicitly mentions additional steps that require a different page or state**
3. ✅ **You can clearly explain what is missing and why CONTINUE is necessary**

### Specific Cases for CONTINUE:

**Case 1: Multi-step Task**
- Task contains words like "and then", "after that"

**Case 2: Hidden Controls Requiring Interaction**
- Task needs a control that is NOT in the current page description
- Example: Task says "select category 'Electronics'" but no category dropdown is visible
- You must first click a button to reveal the dropdown → ✓ CONTINUE
- Counter-example: All form fields are already visible → ✗ NO CONTINUE

**Case 3: Task Spans Multiple States (with clear evidence)**
- Task: "Search for 'laptop' and select the first result"
- Current page: Search box → After search, results appear on NEW page → ✓ CONTINUE
- Counter-example: Task: "Submit the registration form" → Just submit, no need to wait → ✗ NO CONTINUE

**Case 4: Required Components Not Yet Visible**
- Task requires interacting with components (forms, dialogs, panels) that are not in the current DOM
- Example: Task says "add a new item" but only an "Add" button is visible with no form fields
- You must first click the button to reveal the form → ✓ CONTINUE
- The form/dialog will appear after the interaction, requiring a new DOM state to complete the task

## When NOT to Use CONTINUE (Most Common Cases)

**DO NOT use CONTINUE if**:

❌ **Simple form filling/submission**
   - Task: "Fill and submit the login form"
   - All fields and submit button are visible → Just do it, NO CONTINUE

❌ **Single-step actions**
   - Task: "Click the 'Add to Cart' button"
   - Button is visible → Just click it, NO CONTINUE

❌ **Form submission without explicit follow-up**
   - Task: "Register a new account"

❌ **All steps of a multi-step task have already been completed**
   - Task involves multiple steps, but all have been carried out successfully and the task is effectively finished → NO CONTINUE.
